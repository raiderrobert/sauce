# Writing Plainly

Use the user's own rewrites as the standard. Plain writing should sound like them, not like a generic house style.

## Examples

Read [the PR description before and after](examples/pr-description.md) before drafting or editing. The user's rewrite shows the intended voice; the original is a counterexample, not a template.

Explain what the reader needs to know. Keep useful requirements and precise names. Leave out an inventory of the work unless the reader needs it.

The example is not a length limit or a ban on headings, lists, or verification details. Keep required sections and information the reader needs to act safely or understand a limitation. Match the amount of detail to the task rather than forcing every document into two paragraphs.

Return the requested writing. Explain the edits when asked, rather than attaching a style review to every draft.

## Adding examples

Keep the original and the user-approved rewrite together, with a short note about what changed. Preserve the user's wording rather than silently polishing it. Label assistant suggestions as suggestions until the user approves them.

Add examples as the user supplies them. One PR description does not establish their voice for every kind of writing.
