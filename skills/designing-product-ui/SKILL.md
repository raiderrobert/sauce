# Designing Product UI

## Overview

Concrete UI/UX heuristics, each cited to the source and timestamp it came from. Use them to make design decisions while building, and as a checklist when reviewing a screen. The rules are opinions from working designers, not standards; when a rule conflicts with the product's existing design system, follow the system and note the conflict.

## Core Checklist

The rules repeated across the most sources. Check these first on any screen; details and citations are in the routed files.

- Let the data shape the UI: pick the display (chips, timeline, chart, table) that fits the data, not a default table. (`data-and-dashboards.md`)
- Rank every element by importance, then express rank with size, weight, color and opacity contrast, not size alone. (`layout-and-hierarchy.md`)
- Put all spacing on a 4px or 8px grid; keep padding generous and consistent across sibling cards. (`layout-and-hierarchy.md`)
- Use one sans-serif font, at most two weights and two text colors (primary and ~40-70% opacity secondary). (`typography.md`)
- Use color to carry meaning (status, urgency, the one primary action), never as decoration; keep icons uncolored. (`color.md`)
- Tint neutrals and avoid pure black and pure white; in dark mode, make raised surfaces lighter and space neutral steps wider than in light mode. (`color.md`)
- Include semantic colors even in monochrome brands, and check every colored pair against WCAG contrast. (`color.md`)
- Soften shadows (15-20% opacity, large blur) and use one corner radius and one icon library throughout. (`depth-and-polish.md`)
- Give every action a visible response: hover, pressed, loading, success, and an empty state with a call to action. (`components-and-states.md`)
- Give every chart grid lines and axis values; prefer simple line and bar charts. (`data-and-dashboards.md`)
- Hide secondary actions until needed (hover, popover, kebab menu); keep the primary action visible and labeled. (`navigation-and-disclosure.md`)
- Sequence onboarding one step at a time instead of explaining everything in a modal. (`navigation-and-disclosure.md`)
- Animate only to add clarity or direct focus; keep motion subtle. (`motion.md`)
- On landing pages, show the real product UI and lead with a short, specific headline. (`landing-pages.md`)

## Common Mistakes

Tells that a UI was built by a beginner or generated by AI without design review.

| Mistake | Fix |
|---------|-----|
| Brand color on everything, several accents competing | Reserve the accent for the one action that matters; tint low-importance elements |
| Emojis or mixed icon sets | One icon library with matching stroke, fill and size |
| Charts with no axes or grid lines, decorative chart types | Simple line or bar charts with grid lines, axis values and labels |
| Blank screens when there is no data | Empty state with a message and a call to action |
| Every action shown as a permanent button | Progressive disclosure: hover reveals, popovers, menus |
| No tooltips on icons or ambiguous labels | Tooltips or text labels |
| Nested cards, borders on borders, heavy default shadows | One simple border or a soft shadow |
| The same KPIs repeated across pages | Show each piece of data once, where it is used |
| Layout and colors accepted as the AI produced them | Make the layout and color decisions deliberately, then build |
| Dark mode made by inverting light mode | Design dark mode as its own palette with lighter raised surfaces |
